     Plan: Build features/recordings page

     Context

     Velt's marketing site already has a features/comments page driven by a
     Sanity featurePage document and rendered by app/features/[slug]/page.tsx.
     The site is built so that adding a new feature page is mostly a Sanity-data
      exercise: a new featurePage document + assets is enough to ship a new
     route. The user wants to add /features/recordings, matching the Figma at
     node 219:18857 (file HqWIZdR6ISJmaG2n4o3gr8).

     The page bottom (Our Customers Trust Us → FAQ → Get Started → Footer) is
     already covered by the shared sections in [slug]/page.tsx. The
     trusted-logos band (TrustedLogos) is also already wired in. What's new:

     1. A hero with the same PageHero chrome as comments but recordings copy.
     2. A dark video-player demo block under the hero (Audio / Video / Screen /
     All tabs) — should mirror CommentsDemoSidebar's structure so we can wire
     real iframes/GitHub links later. For now, the iframe stage shows a static
     screenshot from Figma.
     3. Three stacked "section cards", each reusing the outer chrome of
     FeatureCardRow (white card · dark border · centered heading + subheading +
     purple CTA · attached dark testimonial banner) but with a single full-width
      image inside instead of a grid of demo cells.

     The Figma cards' inner content is a single oversized PNG (with floating
     chips like "Closed Captions", "Feedback Tools", etc. baked into the image).
      User confirmed: copy the images directly from the Figma file and embed
     them.

     Approach

     1. New section type: featureImageCardSection

     FeatureCardRow's grid is built around equal-width CardCells with fixed
     440px height, an icon+title at top:48.5, a right-edge fade gradient, and a
     "View Docs" footer at top:379.5. None of that fits the Figma cards, which
     are a single full-width image with no internal text/chrome.

     Rather than overload FeatureCardRow with a "single big image" mode (which
     would mean three conditional branches inside CardCell), add a new section
     type that reuses the outer chrome but supplies its own card body:

     - Component: components/feature/FeatureImageCard.tsx
       - Same outer wrapper as FeatureCardRow: 1280-wide white card, 2px #0e0d36
      border, 32 radius, header block (eyebrow + heading + subheading + primary
     CTA), and the TestimonialFooter sub-component. Extract TestimonialFooter
     and the header block from FeatureCardRow into shared helpers (or re-export
     and reuse them) to avoid drift — see "Refactor" below.
       - Body: a single absolute-positioned <img> with configurable
     width/height/bottom-offset to mirror the Figma exactly. Card 1 and Card 3
     are 1280×467 with bottom: -2.38px; Card 2 is 1199×297 with bottom: 68.62px.
     - Schema: add featureImageCardSection in sanity/schemas/featurePage.ts with
      fields: heading, subheading, primaryCta, image (Sanity image), imageWidth,
      imageHeight, imageBottomOffset, and inlineTestimonial (reuse the existing
     inlineTestimonial type used by featureCardRowSection).
     - Dispatcher: register featureImageCardSection in
     components/feature/FeatureSections.tsx alongside the existing eight section
      types.
     - Sanity index: export the new schema from sanity/schemas/index.ts (the
     featurePage types are aggregated there).

     Refactor: extract shared chrome

     FeatureCardRow and the new FeatureImageCard share the outer card frame, the
      centered heading/subheading/CTA stack, and the dark testimonial footer.
     Extract these into:

     - components/feature/FeatureSectionShell.tsx
       - <FeatureSectionShell heading subheading eyebrow viewDocsCta primaryCta 
     testimonial>{children}</FeatureSectionShell>
       - Renders: outer <section> + 1280×… white bordered card + header block +
     slot for children + optional <TestimonialFooter>.
     - Update FeatureCardRow to use FeatureSectionShell and pass its grid of
     CardCells as children. This is a non-functional refactor; existing behavior
      is preserved.
     - FeatureImageCard uses FeatureSectionShell and passes a single <img> block
      as children.
